# r4.2 穿书开场回归修复 · 2026-10-13

## 为什么修

玩家明确要求：穿书经过和新手引导是正文，不能把“先看看完整穿书经过（可选）”藏在折叠层。旧 r4.2 为提前给第一次有效选择，把 `ENTRY_WAKE` 全文藏在 `<details>` 内，默认开屏只看见结局速览与三个按钮。此举破坏现实→醒来→找线索→认书→惊惧→原著先知→自主改命的因果铺垫。

## 此次真正变更

- `data/STORY.json`: 仍是 `ENTRY_WAKE` 的同一个正式故事节点，扩为 28 段亲历叙事，保留第十三章、第七天、19:03、书名、场务工牌、四位女主的原著命运与曾读到的秘密、陆景行、阿衡等已确认世界观；**不杜撰首演原著的章节编号**。
- `tools/preview-ui.js`: 首屏正常分页阅读正式 JSON，阅读完才显示三个真实选择和原著行动—后果—先知线索。移除“可选查看完整穿书经过”折叠；恢复阅读位置，阅读行为不计入选择，不强制“无意义的单按钮剧情动作”。
- `tools/preview-ui.js`: 修复以前特殊放行 `ENTRY_WAKE` 未读完就允许执行 choice 的例外，统一要求 `currentPage().last` 才能选择。
- `tools/preview.css`: 阅读阶段用紧凑排版，手机上清楚展示每段内容与页数，保护字体放大模式。
- 旧保存键 `gonglue:revision-r4.2:canonical` 不覆盖；本轮使用新键 `gonglue:revision-r4.2-intro:canonical`。老版本旧进度保留，不偷偷迁移到剧情已变的存档。剧情哈希和文本内置一致性须重新验证。
- `tools/test-ui-r4.py`: 新增必读穿书、无跳步首选、阅读不计动作、读到一半恢复测试；更新上一轮“必须第一屏立刻展示三个选择”的错误断言。

## 体验判准

玩家在第一个决定前，必须亲历从现实头晕到舞台苏醒、工作证与陌生身体、听见小说人物名字、掐手心确认不是梦、回忆原著里的行动与第七天责任，之后再选：

1. **照原著走**：守设备箱，陆景行钢琴救场，仍有第七天危机；可以后续拒签或留证改变命运。
2. **先改首演**：找到蓝带原版，交专业音控核对，改变唐映雪被救场方式。
3. **先查真相**：记录错版证据，寻找原著未出现的矛盾，再选择如何救场。

这些分支原有 `id`、`effects`、`next` 均保持不动。四位女主不是上来就挑的攻略对象，最终关系仍需真实相处与同意。
