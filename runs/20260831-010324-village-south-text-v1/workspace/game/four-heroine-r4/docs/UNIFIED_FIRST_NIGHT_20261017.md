## 关键诊断
此前视觉分支采用独立整幅 CG，但交互分支使用背景、人物、CSS 工牌拼装，彼此分叉。人像方图作为 `cover` 全屏造成错误裁切与低清晰度。V7 新工作人员与工牌为 941×1672 候选，不是 1536×2560 已核准 master。演出中的歌手仍复用喝水人像，不能表达事故现场。需要用同一个真实场景镜头替换。

## 统一视觉规范
- 现代都市艺术中心，演出后台、专业设备、舞台与侧幕；暖琥珀主灯、蓝紫边光，真实连续的空间、光源和反射。
- 每一张事件 CG 是**独立的完整镜头**，无边框、无对话框、无按钮、无拼贴抠像、无可见水印。
- 女主唐映雪作为歌手须具有台前动作、耳返、演出服、实际表演状态；沈清辞是解决危机的后台关键人物。其他三位正典女主在后续剧情保持既有身份与外形一致性。
- 许照采用第一人称 POV，只在剧情要求的主观物体或手部出现，不让玩家被立绘挡住；工作人员是普通职业男性，功能性耳麦和服装，不使用偶像剧式近景打光。
- 镜头构图优先真实 H5 390×844 / 320×568 的可见阶段；焦点放在主舞台上半部，脸部、手指、工牌与音控线索不可被底部对话框切断。
- master 推荐 1536×2560 竖屏，最小交付 1536×2400 且比例兼容；以**屏幕上实际源像素密度**和真实浏览器截图而非仅文件大小验收。对低规格设备须有适当自适应清晰度。未通过资源标注 `candidate` 不充作 `approved`。

## 正典保护与玩法
- `STORY.json` / `engine.mjs` 保持不动；中途旧存档继承原兼容逻辑，`?qa=canonical` 保留历史审计入口。
- 第一次互动来自剧务伸手，回答给不同即时反应；牌面需要玩家点击，后台各线索需要自行选择调查，蓝标盘未被查看前不能前往关键选择。
- 最终的 `canon`（核对交接）、`rescue`（救场）、`investigate`（留证）调用原引擎真实动作；后续 10 个节点继续通过 `interactive-follow.js` 映射正典动作。
- 底部一人一段，正文约 15–35 中文字符；全部可点控件 ≥44px，高度通常 ≤ 1/4，矮屏不超过 1/3，无内部滚动；点击主体区域可推进纯单步对话，含决策时不得意外跳过。
