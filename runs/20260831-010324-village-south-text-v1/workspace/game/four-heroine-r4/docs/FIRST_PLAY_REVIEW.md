# 首局体验第二轮自查 · r4

## 已经进入游戏的变化
首屏是一个人突然头晕醒来，被叫“许照”，而不是“我已经知道自己穿书”。第一次可按按钮是看工作证。
随后从多人称呼、场地、事故和钢琴救场辨认小说；紧张、掐手心、缓口气之后才行动。屏幕中的18:59—19:03是**剧情时钟**，不是玩家阅读用时。

第一次改命可选不同方法：先和歌手确认接段、听制作人统一调度、留存切换画面、当场核授权、自己把物件交给音控。
五条都让能做事的人继续做事。陆景行准备钢琴并参与过渡，不会为了夸主角突然失去判断。不同方案后来由不同人回忆，公开质疑授权还会带来程放追问。

首胜后有陌生手机/住处的小段适应，再开始和一个真实的人聊天。初见是感谢和好奇；私人兴趣、约会、交往、朋友与排他并非同一开关。
唐映雪会用玩笑掩饰紧张；沈清辞关心安排但也会承认自己选错；林见月会观察、追问，也有与陆景行相关的旧感情和自己的拍片目标；顾晚棠直接、会调侃，也确实做错过利益决定。不是四个同语气的奖励按钮。

## 成长与回来玩的理由
近目标是把演出救下来、留下能说明分工的记录、弄明白下一次谁愿意单独见你。
中目标是亲手改变第七天的退场，逐渐把关系从兴趣变成有真实共同经历的往来。
后目标是自己的工作成果、四个人的职业决定、与陆景行新的竞争/合作，以及亲密关系范围和去留。
回退历史可以比较首次方案与后续回调；未选分支和不同组合有新情景。没有加签到、体力或机械送礼来假装留存。

## 本轮真正做过的体验检查
作者逐场复读并编辑225场；还读了40尾声、8番外、6收束与手册。记录是自查，不是另一位独立真人。
Chromium离线注入入口做普通点击，四人路线95次真实界面选择至结局；查看并回退历史。
12项UI用例覆盖首次五路、拖动与双击、坏档、恢复及四种尺寸；5项阅读器用例覆盖完整路线、24结局、8番外、40尾声与模拟存档失败。
截图是浏览器模拟尺寸，不是一部真实手机。

## 不作“已达标”结论的部分
前30秒、3—5分钟、10—20分钟吸引力没有真人实测。`qa/current/experience-model.json`只是字数与假定速度计算，不作验收依据，更不是留存率。
临时SVG和缺少声音会影响吸引力，不能称正式美术已完成。多线日程在长时间游玩中是否机械，仍需盲测。

## 真人盲测记录模板（空白待填）
找未看设定的成年新玩家，不给路线，不提前解释“哪个选项对”。
记录真实开始/结束时间、首次操作、哪里认出穿书、首个不懂的原句、第一次想退出的节点、最想再见的角色及原因。
30秒问“刚才发生了什么”；3—5分钟问“为什么她会注意你”；10—20分钟看是否自然继续，不以完成问卷代替继续玩。
不要把自动化快速点击录像、作者自评或模型模拟玩家冒充这些记录。

## TapTap参考边界
两张用户截图是独立开发者自述；本轮只吸收首局兑现承诺、详情页清楚展示体验、具体长期目标、持续成长与进度可靠性。
不把图片中的曝光、转化或游玩中位数移植成本作指标；没有核实TapTap算法，也没有本作商店/留存数据。
建议详情页只宣传已经能玩的事实：“穿成炮灰许照，认出熟悉的救场桥段；这一次，试着改写第七天的退场。”
