# 第一夜交互重做｜可玩样板与制作限制（2026-10-16）

## 为什么不是“缩短对白”

用户在 PR #20 实际试玩发现：主角自动回答、旁白代为搜索 U 盘、原著人名与任务说明同时灌入；即使缩小对白框、按句分页，玩家仍只是不断点击“继续”。

这次需要改的是**玩家必须自己行动**，不是让原来的叙述变成更多分页。

## 默认第一夜玩法

| 节点 | 玩家亲手做什么 | 可见结果 |
|---|---|---|
| 醒来 | 选择让沈清辞扶、自己站起或追问名字 | 沈清辞针对回答立即改变语气 |
| 陌生身份 | 点击工牌 | 得知主角是小说里会被清退的许照，而不是读一段穿越设定 |
| 演出事故 | 听见唐映雪与沈清辞的短对白 | 理解“伴奏出了问题”这一件事 |
| 是否插手 | 先帮沈、问唐、自己判断 | 各有一次不同的角色反馈 |
| 后台搜证 | 分别点控台、交接单、接线板 | 玩家自己获得“版本不同”“等待签字”“蓝标 U 盘” |
| 程放拦阻 | 追问、藏好发现、要求核验 | 程放产生不同回应 |
| 重大决定 | 救场 / 核验证据 / 拒绝背锅 | 调用现有真实 `ENTRY_WAKE` 三分支，保持原有后续结局 |

没有找到蓝标 U 盘就不能从搜证环节直接进入最后一刻。没有任何前置微选择伪装成正典命令；只有三个原引擎选择才进入 `commands`。

## 限制器 v1

**要被实际验收的规则：**

1. 玩家第一屏就有对话选择；不需要被动阅读 28 个节拍。
2. 每一屏只有一个说话人、一个文本块；当前样板的正文目标约 15–35 汉字，测试上限 44 字，不存在可滚动长旁白。
3. 普通竖屏对白层目标 ≤ 屏幕 1/4，特殊矮屏 ≤ 1/3；有效触点高度 ≥44px。
4. “查看工牌”“检查接线板”必须由用户点击触发，原著线索不会凭空获得。
5. 每个重要选项 1–3 次推进内得到人物反应；三大决策进入原正典后果，不是三种写法相同的按钮。
6. 调查进度、主角态度、先求助谁、怎样回应程放进入 `ui.firstNight`，刷新/菜单/导入导出不丢失。
7. 原 228 个场景、751 个原始选择、16 个二阶段决定和主线命令模型保留；执行 `npm run verify` 与真实浏览器路线回归。
8. 第一夜旧存档位于原 `ENTRY_WAKE` 中途时，不用新页码误跳过去；旧记录仍可按正典兼容模式阅读。

## 技术边界

- `tools/interactive-opening.js` 是面向玩家的编导剧情层，切换 `storyHTML` 展示，最后通过 `choose(state,DATA, id,revision)` 进入正典，既不是截图 Demo，也不修改故事引擎。
- `tools/interactive-opening.css` 使用仓库已有授权立绘与场景图、CSS 道具，不依赖外部图片域名。
- `tools/test-interactive-opening.py` 通过 HTTP/浏览器触屏复验原生存档、调查、拒绝旁白跳关、三条真正命令、布局，Chromium 与 WebKit 都需要有证据。
- 旧版来源检查、剧情图和迁移验收通过显式 `?qa=canonical` 只读完整旧场景，不得冒充默认玩家体验；真正的默认入口必须单独通过新验收。
- `STORY.json` 当前未被重写。**这是前五分钟交互垂直样板，不是全 228 场景已完成剧本改稿。** 验证体验方向后，需把正式编导结构迁入可编辑剧情数据与审计体系，并逐章清除“旁白替玩家做事”的缺陷。

## 第一夜后续节点（避免做完第一次选择又掉回小说）

对玩家端开放的十个早期主线节点增加 `interactive-follow.js` 编导层：
`ENTRY_MEMORY`、`ENTRY_CLUES`、`COLD`、`OP_SETTLE`、`OP_FORK`、`OP_CANON`、
`OP_TALK_t`、`OP_TALK_s`、`OP_TALK_l`、`OP_TALK_g`。

这十个节点把长解释改为一位人物的短对白，加上玩家明确点击的原引擎选项。求助、存证、拒签及与四位女主的接触，不再通过“你发现了”“你决定了”跳过。角色对白与选项仍然保留各分支的不同后果；`OP_SETTLE` 不展示内部 `continue` 作为一个虚假的玩家选项。

老工程的 `?qa=canonical` 可重现旧 28 段，只用于来源与存档兼容性审计；默认真实玩家端不显示旧开场。

## 可接受范围（截至此 PR）

第一夜可玩样板已延伸至上述十个直接衔接场景，但其他中后期正文依然可能出现过长旁白。**不能宣称全章节已完成导演化改写**。下一阶段必须把互动编排转入长期维护的数据模型；测试源代码是否通过，不等于目标玩家是否会继续玩。
