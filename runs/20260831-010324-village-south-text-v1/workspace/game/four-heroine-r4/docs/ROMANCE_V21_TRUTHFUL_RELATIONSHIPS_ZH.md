# 《攻略美少女》V21｜恋爱台词、真实承诺与后果保持一致

## 为什么继续改

V20 解决了主线行动的抽象分类、邀约事件与原作不一致等问题，工程完整浏览器 CI 已通过。但 V11 仍存在具体的逻辑穿帮：s03、l03、g03 的“开放约会”已经通过唯一正典引擎记录 active=true、scope=open、commitment=dating，女主却回答“我还没答应”“需要想想”，导致玩家以为被拒绝，后续故事却当成已经在交往。

此外，当玩家已经答应唐映雪等人“只跟你交往”，再对另一位女主作同样的承诺时，之前的按钮仍只显示泛泛的“之后得负责”，完全不提示玩家正在违背怎样的具体承诺。第 21 天 A7a 的多段恋爱收尾，在 0 人或 1 人交往的存档中仍说“让她们自己选”，甚至可以被误认为强行发放多个恋人。

## 完成的真实改动

- t03/s03/l03/g03 的 open 正式约会回应清楚表示双方同意试着约会（**不是独占**），分别约好后续的一次见面；4 个 open 指向原 active=true 的引擎写入，拒绝用“再想想”掩盖状态变化。
- 新增纯展示层 helpers：tools/romance-v21-context.mjs。只读取已记录的 active_*/scope_*；如果已在其他关系中，优先提醒独占承诺，其次提醒开放约会。只有在当前场景真的有历史关系时提示，绝不假造已认识的人，也不会强制禁止玩家选择说谎。
- 女主新邀约处的主角心声根据真实已有承诺增加一句，放在女主最终发问**之前**，最后仍由女主本人提出具体问题；不替玩家自动说一句已同意或已拒绝。旧 V11 存档位置安全延续。
- A7a 第 21 天根据活跃关系数量（0、1、2+）调整**演出标签和选后心声**：无恋人不谎称“她们都在等”；单恋人用单数；多人关系保留原本的诚实披露、可能失去关系的风险，不改正典 closing_mode/ending。
- A3a 离开、A3b 不赴约、A4a 不帮忙、A5a 不介入、s03 只做朋友、l03 只做朋友、g03 明确拒绝等 7 个具体选项增加克制但可察觉的选后人物反应；不伪造人物即时知道秘密，避免无代价和无差异按钮。
- 不改 STORY.json、engine.mjs、228 场和 24 种结局，不引入好感值或额外评分。以上是**实际玩家看到的剧情投影与结果**，没有修改原 choices/effects，旧存档可回放。源码 V21 helper 作为单文件 H5 的脚本内联，纯 JS 单元测试可直接 import。

## 新增门禁

- test-romance-v21.mjs：四位女主 open 真正执行引擎 intent:date+open、检查 active/scope/commitment 与 replay、自然回答不矛盾；模拟旧独占/开放承诺、临界状态和 A7a 0/1/2+ 路线展示；检验正典数据 SHA-256 未变。
- test-romance-v21.py：在真实 HTTP Chromium/WebKit 打开四个可约会节点，通过触控点击 open，核验真实两段历史、双方开始约会与角色后续一句自然邀约、刷新延续；单独使用**展示层合成标志**检查已有独占承诺提示和 A7a 0/1/2+ 标签，但合成标志从不提交成游戏历史。所有旧 V9–V20 双浏览器回归保留。

## 不可以夸大的事

这证明显示的关系和游戏记录没有互相矛盾，但不意味着文字已经过陌生人的理解测试。大量生活／约会仍复用舞台 CG，必须补有权利证明、人物统一的高清实景；实体 iPhone/Android 及 8–12 位首次接触玩家的盲玩尚未完成。保持 Draft PR #22，不能合并 main 或发布。

## WebKit 真实测试提取方式修复

V21 第一轮 Chromium 全部通过，WebKit 四条约会在按下实际按钮、历史写入、角色回应存在均已通过后，测试用 `innerText` 严格比较整句对白时失败。`innerText` 是带浏览器排版语义的输出，在引擎间不保证一致。现在改为读取对白 `<p>` 节点的精确 `textContent` 并严格比对完整来源字符串，同时明确断言文本实际可见，且刚按下选择时 `v11.after.step===0`，可抓出双重事件误跳过第一句的真实缺陷。将 V21 专项测试移动到漫长的全量触屏回归最前面，失败时能在数分钟内得到有证据的日志，不缩减全部 Chromium/WebKit 旧用例。
