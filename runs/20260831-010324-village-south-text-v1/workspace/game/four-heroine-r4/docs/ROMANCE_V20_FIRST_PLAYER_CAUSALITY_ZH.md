# 《攻略美少女》V20｜从玩家视角修正文案与真实选择

## 真正的问题

V19 改善了 36 场女主对话的因果，主线仍存在三个硬伤：第四晚的顾晚棠原著约的是后街吃面却写成对账；第五天林见月报名独立拍摄的截止日被写成短片当晚交片；第七天假视频的剪辑造假与隐私录音不能直接公开的关系没有交代清楚。此外 12 场重要决策需要先选抽象‘创作方向／现实安排’，再在下一页选真正行动。玩家不应该帮程序分类。

## 已修改的演出

- 13 个关键节点改写：A1b、A2b、A3b、A4a、A4b、A5a、A5b、A6a、A7a、t03、s03、l03、g03；每场 2–3 个简短单人对白回合。
- 第四晚四条公开邀请说清排歌、试灯、剪辑室看片、后街面馆吃饭；没有认识顾晚棠之前只称面馆，不突然断言自己已认识她。
- 第五天的独立拍摄项目是报名截止，不是短片提交截止。视频里拍到别人哭，需要单独征得同意。林见月的录音只需节选能作证的部分，不连带传播他人隐私。
- 第七天不利视频只截取许照接近设备箱，假字幕称其操作失误，并不能证明他导出坏伴奏。按历史证据不同，正确说明目前掌握了什么；不在有可用证据时说玩家手上什么都没有。
- 唐映雪、沈清辞、林见月、顾晚棠四条正式表白明确今天是约会，不是无缘无故在工作饭桌上要求确定关系。

## 不再先问抽象分类

18 个关键场景默认直接展示所有合法的具体剧情叶子选项。12 个原来采用 decisionSteps 的节点，玩家只点一次具体行动，播放器在内部依次执行原引擎的 intent:group 命令和叶子 action 命令，真实存储两条历史，最后显示本来应有的角色反应。没有创造假分支，没有重写引擎效果。若旧存档已有中间 intent，则继续从该阶段恢复。?qa=intent 保留旧双层操作供回归和历史兼容。

手机 320×568 / 390×844 / 430×932 的选项与分页不截断；分页按钮从 42px 修至至少 46px。

## QA

test-romance-v20.mjs 对照原始正典：18 个场景 79 个底层选项、源情节一致；在实际 fixtures 中复验 78 条可选叶子行动，其中 60 条必须记录完整的两步 canonical 命令，回放后 flags 与后续场景一致。

test-romance-v20.py 在真实 HTTP Chromium/WebKit 触屏验证全部 18 场的行动可见性、选项真实性、触控尺寸、每屏一人、按钮反馈、存档刷新及记录完整性。?qa=intent 下原 V11 双层路径测试保留，V13–V19 所有回归继续。

这只是工程范围。原始 STORY.json 与 engine.mjs 未修改，228 场和结局规则不变。真正生活/约会地点的正式高质量授权 CG、物理 iOS/Android 设备和 8–12 名首次玩的成年玩家盲玩未完成。PR 保持 Draft，不合并，不部署。准确成功状态须检查这次提交的 GitHub Actions。
## 真实手机截图二次审校：18 场标题也必须让人看懂

第一轮 V20 的 Chromium/WebKit 工程回归已通过（https://github.com/23chen990/gonglue-meishaonv-game/actions/runs/39054724107），随后人工查看 320×568 手机截图，发现源 STORY.json 的个别章节标题仍然会误导：例如第四晚写“你先答应谁”，好像主角被四位陌生女子同时追求，实际是项目群四条邀请；四条恋爱表白的原标题“今天没有文件夹”“她给你留的第一排”等不能说明是约会。

新增演出层 V11_VISIBLE_HEADINGS：把 18 场顶部提示映射到具体事件，如“第四晚 · 项目群的四条邀请”“第五天 · 独立拍摄报名”“第七天 · 被剪过的宣传视频”“顾晚棠 · 约会邀请”。不改 canon.title，也不修改原著文本；若未覆盖场景则自动回退源标题。V20 mjs 静态检查八个典型标题，Chromium/WebKit 的 A3b 触控测试检查看到的标题确实有“项目群的四条邀请”且没有“先答应谁”。最终 HEAD 必须再跑一次完整工程测试。
