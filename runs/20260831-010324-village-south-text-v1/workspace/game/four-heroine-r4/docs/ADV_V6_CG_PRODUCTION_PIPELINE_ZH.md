# 《攻略美少女》｜从效果图到真实 Galgame CG 的可执行生产规范

版本：ADV V6 生产流程设计稿｜2026-10-16｜适用于 Draft PR #20，**尚非已完成的 V6 素材或游戏**

## 1. 为什么过去的效果图和游戏总是两回事（项目实证）

两份可核对证据：

1. **概念分镜参考图** `/mnt/data/a_vertically_oriented_collage_comic_style_visual_n.png` 是 **1024×1536 的 3×4 分镜拼图**。每格内容约 341×384px，还内嵌中文标题、对白框和选项；即使整张画面看起来统一，也**不能裁成游戏用的独立高清 CG**。大图中“拍得像”的感觉来自每一格内部的人物、透视、灯光和景深一起生成，而不是前端拼图。
2. **V5 实际试玩 HTML 中嵌入的完整图片**尺寸为：工作人员 **909×828**、POV 工作牌 **906×834**、钢琴 **906×828**、林见月 **909×912**、顾晚棠 **906×915**、舞台女孩 **900×906**、U 盘线索 **909×453**、手持 U 盘 **900×489**。单张图片被压缩到约 **20–69 KiB**。它们大多近方形，且没有足够的像素储备，无法稳定适配高 DPR 的竖屏 ADV 舞台。

以工作人员为例，旧画面为 909×828，比目标舞台约 390×633 宽很多。`object-fit: cover` 的缩放比例约 633/828=0.764；最终可见的原图水平范围只有 390/0.764≈510px，相当于**原图约 44% 横向内容被裁掉**。若手机 DPR 为 3，画面在物理像素中约需 1170×1899，却主要由原图约 510×828 的区域放大绘制；因此面部显得过大、细节不够清晰。这是几何与像素的双重问题，换滤镜或 CSS 模糊参数解决不了。

**重要区分：** V5 已把部分羽化贴图替换为单镜头 CG，解决了一种“幽灵人物”错误；但**单镜头 ≠ 高清、构图合格、视觉连续**。V6 需要重新按竖屏重新构图、生成原图，并把游戏真实截图作为验收物。

## 2. 最终目标产物是什么

每个关键剧情画面要有以下四层彼此独立的文件/数据：

| 层 | 应当存在的内容 | 绝对不能混入 |
|---|---|---|
| **高质量清洁 CG Master** | 真实完整场景中的人物、道具、光、影、透视，不带任何 UI | 对白框、浮动说明卡、logo、按钮、分镜框；不能是从九宫格硬截的小图 |
| **生产后期 CG** | 同一张 Master 上校正透视、补局部瑕疵；工牌等必要准确文字以符合透视和光照的方式排入实物表面 | 第二张不相干的场景图硬贴、虚假的透明人物边缘、不合理的五官手指 |
| **派生线上资源** | 对已批准 Master 无损/视觉无损导出 WebP/AVIF，按实际目标分辨率处理，不拉伸 | 把 900px 方图扩成“2K 假高清”、过度压缩的 50KB 面部 CG |
| **游戏原生 UI** | 姓名牌、一次一段对白、继续、选项、菜单、无障碍标签、点击区域 | 把这些写进图片，从而无法适配不同字号、语言与无障碍操作 |

**素材版权与角色肖像的使用权必须留证**，不能把“工具生成成功”当成可商用授权证明；如引用第三方参考画面，必须确保不会直接复制受保护的角色或背景。

## 3. 画幅、清晰度和关键构图

- **正式剧情 CG Master：建议 1536×2560px（3:5 竖幅）或更高。** 此尺寸按目前手机舞台占屏约 3/4 的画幅来选，而不是照着 9:16 口号忽略对话框。保留未压缩 PNG Master；逐镜头生成，不从分镜拼图裁切。
- **为什么不是盲目坚持 9:16？** 例如 390×844 手机，底部对白区 22%–25% 时，实际舞台约为 390×633–658，宽高比约 0.593–0.616，接近 3:5（0.6）。如果后续决定让 CG 填满全屏、对白半透明覆盖，则要重新锁定全屏相应的画幅；不能把两个布局体系混在同一轮素材验收。
- 320×568 的短屏会有比 390×844 更宽的舞台比例，因此**必须独立检查安全裁切**。如果自动裁切遮住了演员面部、道具和关键姿势，就补单独的小屏变体或重新生成构图；不能用 CSS 继续放大人物硬凑。
- **物理像素核算：** 390×633 CSS px 在 DPR=3 时对应约 1170×1899 物理像素。1536×2560 的目标 Master 足够提供更好的采样空间，但清晰不只取决于像素数，源图的人脸、手部和细节必须本来就清楚。
- **品质阈值（候选资源 P0）：** 宽至少 1536px、高至少 2400px；目标纵横比 0.60，允许范围 0.57–0.64，超出必须作单镜头人工取景审批。不能仅凭文件后缀或视频超分判断。超过 120KB 不是质量保证，低于 120KB 只触发视觉人工复查，不自动判失败。
- **镜头安全区：** 人脸焦点通常放在横向中央 25%–75%、纵向上方 15%–57%；手持工牌可稍往下，但要确保在两种设备以及对白区遮挡条件下可辨认。选项背景主要把人物焦点放在上半部，下面留下真实 HTML 按钮的空间。所有这些位置属于构图建议，最终仍以像素截图审查为准。

## 4. 统一美术圣经（必须先锁再大量生产）

1. **风格**：现代都市恋爱视觉小说的电影感半写实数字插画。统一笔触、肤色细节、面部比例；不在同一段里交替使用照片级真人和精致二次元女主。
2. **灯光**：北岸艺术中心后台暖琥珀主光、舞台紫蓝辅助光；同一时间的色温、阴影方向、空气透视必须连续。
3. **工作人员“阿衡”**：成年、普通舞台工作人员，不是偶像；固定黑色短袖、功能性耳麦、工作证挂绳。连续性包括耳麦在同侧、面部轮廓和发型一致。
4. **唐映雪（台上女孩）**：先表现她如何面对事故，而非只把她当美少女海报。服装、耳返和站位前后统一。
5. **主角“我”**：默认第一视角，通过手、视线高度和现场反应塑造身份；不能无故插入一个第三人称“我”的帅气正脸肖像。后续确需出现脸，先建立角色锁定图并解释视角切换。
6. **空间**：后台侧幕 → 器材箱/接线板 → 琴台 → 舞台是一个可连续定位的真实空间，不能随机换舞台建筑结构。最好有一张独立的“空间关系参考图”，而非每次让模型重新猜。
7. **严格禁止**：叠加两个不同摄影角度的背景、人物“幽灵羽化”、任意换脸、画面直接嵌入选项、错误的工牌姓名、已经拿到未寻找的 U 盘、现代人物突然穿不符合剧情的服饰。

**保证人物一致性的方法是“锁角色参考 + 带参考图生成/编辑 + 逐镜审稿”，不是仅靠同一个 seed 或一句提示词。** 角色面部、服装、镜头、场景四种连续性都要审。

## 5. 一次完成一个正式 CG 的生产流水线

1. **导演卡签审（文字阶段）**：填写 `shotId`、`sourceRowIds`、焦点、说话者、镜头距离、地点、人物动作、观众需要懂的事实和所需 UI 安全区。没有这张卡，不生成图。
2. **确定参考资料**：角色定妆、服装与配饰、舞台地点、灯光图和上一镜的完成稿。效果图分镜只能当“构图/氛围参考”，不当正式素材源。
3. **独立生成高清清洁 CG**：一个镜头一张图；不得让模型生成带对白框的整页 Galgame UI，不允许从拼图截取。采用相同的角色参考与美术规范。
4. **第一轮美术检查**：100% 放大检查眼睛、发丝、耳麦、手指、手牌挂绳、钢琴键、背景透视、演员与环境的接触边界。如果明显模糊或“人物贴上去”，直接退回**重新生成原图**，不靠 CSS 羽化补救。
5. **后期制作**：仅在同一个完整镜头内部调整局部瑕疵和真实道具表面排字，确保文字符合物体透视；保留 Master 的图层/版本及溯源记录（不得向用户分享受限字体文件）。
6. **多裁切安全检查**：用真实的 320×568、360×780、390×844、430×932 的游戏模板预览，必要时为短屏保留 `compactCrop` 或单独绘制版本。禁止单凭原图好看签审。
7. **网页派生**：从批准 Master 输出 WebP/AVIF，保留版本、原始宽高、Hash、制作来源与授权状态。禁止把低分辨率旧图放大后伪装成 Master。
8. **正式 H5 里验收**：CG 与对话、字幕行数、选项和点击点位同时渲染；检查主角/背景是否同画面、遮挡、色温和清晰度。
9. **先批准再改绑定**：只有 `visualReview=approved` 且 `licenseReview=approved`、技术尺寸符合要求时，才把 `shotId→approved asset` 写到播放器映射中。旧图保留作回退但不参与生成最终演出图。
10. **回归验收**：所有三个选择 ID、存档/读档、历史、字体、WebKit/Chromium、原始引擎不变；然后真人前 30 秒盲玩。

## 6. 从资源映射到客户端：哪些属于代码，哪些不该让 CSS 做

建议建立**独立镜头 manifest**（交付包内 `03_shot_manifest.json`）。其中 `sourceRowId` 对应原始剧情行，`shotId` 对应正式 CG，`asset` 指向图片，`speaker` 和 `line` 是前台显示用演出文案；真实选项 ID 仍由正典引擎决定。

```
Current canonical state + source row
             ↓
      Director shot lookup
             ↓
  Approved single CG asset (one image)
             ↓
  True UI: name / dialogue / choices
             ↓
     Canonical choice / replay
```

- **单镜头模式**：主舞台应只有一张真正显示的 `<img>`，而不是背后再留 `.mobile-scenery` 和人物图层。`filter`/`mask` 不用于把另一张照片混进来。
- **文字**：真正的 HTML DOM；姓名牌与台词同一播放器状态源，避免“说的人不在画面、名字错挂”。`aria-live` 只报告当前段；台词不滚动，长句按字形测量分页。
- **响应式**：普通对白框以屏高约 18%–22% 为适应目标，最大 1/4；大字体与短屏可到 1/3。核心是不能出现“只有一行文字却留出 150px 空黑块”，也不能缩字硬塞；允许根据文字长度和可用高度调整，但保持框体位置稳定、避免频繁抖动。
- **选择态**：当前对话框可收起，三项真实行动在下方浮层；最小触控面积 44×44 CSS px，不滚动，不遮住正在发生的舞台重点。
- **镜头切换**：优先直接切换或 100–200ms 的轻量淡入，禁止用 CSS 大幅 zoom 模拟“高清”，禁止拉伸失真和跨图硬羽化。
- **低网速**：下一镜图片可预加载，避免点击后白屏；可以用一张已批准的低清预览做 LQIP（仅短暂加载占位），最后必须替换成批准的高清版本，不能一直展示缩略图。

## 7. 必须实际执行的验收（两类门槛）

### A. 自动化能证明什么

- 镜头清单的路径确实存在且指向单独 WebP/PNG；分辨率/纵横比达标，不能把横图充当竖图；没有从旧 `scene_*` 羽化图重新引入旧病。
- 任一时刻剧情舞台只有一张 CG；图片 `naturalWidth/naturalHeight` 达到承诺值；裁切后重点未超出屏幕（焦点须人工复核）。
- 320 / 360 / 375 / 390 / 430px 下不横向溢出、对白一次一人、不滚动、选项三条可触摸；点击道具再关闭、菜单改字号、旧存档恢复都不跳剧情；音频静音也能读懂。
- `canon/rescue/investigate` ID、历史命令序列与原引擎测试不变化。V5 的 2026-10-16 最终 CI 有工程通过记录，但**绝不等于 V6 新素材画质通过**。

### B. 必须由实际游戏截图 + 真人体验证明什么

| P0 问题 | 不能接受的现象 | 真正合格的证据 |
|---|---|---|
| 图片清晰 | 近方形 900px CG 放大、脸部颗粒模糊、低清马赛克 | 游戏 390px 宽度截图 + 主图 100% 像素检查；细节清楚，不是插值假的清晰 |
| 人物融合 | 身体透出后台、不同光源、人物像贴纸 | CG 源图和实机图都能解释人物与环境的真实空间关系 |
| POV 自然 | 工牌飘在正中央，像信息卡 | 真实手部姿势、挂绳与地面透视，工牌在手里且能读清身份 |
| 一致性 | 同一个工作人员换脸、耳麦时左时右、场地突然变化 | 连续镜头联系表 + 人物定妆参考 + 分镜审查签字 |
| 恋爱吸引力 | 女主只出一张美丽海报，没有困境与反应 | 玩家能说明“她遇到了什么困境，我为什么想帮助她” |
| 玩家行动 | 选项像问卷，选完跳一大段解释 | 点击后 1–2 次继续内出现与行动对应的事件画面/反馈 |
| 故事密度 | 30 秒里需要背 5 个人名和多条专业名词 | 玩家主要能复述“我是许照、伴奏出错、七天后会背锅、我能决定怎么做” |

每张镜头都要把**原图、390×844 真实浏览器截图、320×568 小屏截图**放在同一份审查材料中；没有实机渲染证据不允许声称“与效果图一致”。

## 8. 本轮范围与交付顺序（防止为了赶数量再次降级）

**P0：** OP01 人物唤醒、OP02 工作牌、OP03 舞台出错、OP04 钢琴、OP05 回忆、OP06 线索、OP07 首次选择的 7 张独立 CG。每张过关后再提交完整首 30 秒真实 H5。

**P1：** 分叉的 3 张直接后果 CG，保证 `canon` 和 `rescue/investigate` 画面没有提前拿到盘等错位；然后重做前 5–10 分钟。

**P2：** 建立女主一致性角色包、表情差分与常规对白系统，按 228 场的剧情优先级扩展。不是 228 场必须有 228 张 CG；普通对话应使用美术一致的真实透明角色立绘，关键事件才用整张 CG，不能靠不透明肖像硬叠。

**V6 不能宣称“完成”的条件**：上述全部独立 CG 都未达到人工视觉通过；真实 H5 尚未对比截图；WebKit/Chromium + 存档/引擎还没过，或目标用户前 30 秒没人验证。本交付的是能启动这条流水线的**生产合同与验收工具**，不冒充新的高清素材已制作。
