# 《攻略美少女》V11｜中后段真正让人懂得选、看见代价

## 问题与判定

V10 已让第一夜的救场、背锅、留证与四位女主初次互动产生正典后果，但从第一夜交接到第七天翻案，玩家又回到大量旁白、含糊选项、做了选择要读多屏才知道得失的客户端形态。这是「正文里有真正的因果、手机端却难以感知」的表现层结构问题，不能只删两句话或直接加好感值。

## 改造范围（已入游戏源文件）

- 使用 `tools/romance-v11-arcs.json` 作为**18 个关键剧情场景 / 79 个真实底层选择**的舞台导演表，`tools/romance-v11.js` 将其映射到现有 `renderScene()` 和 `choose()`。
- 主线：`A1b`（签收责任）、`A2a`（被抢署名）、`A2b`（群里追责）、`A3a`（剧场去留）、`A3b`（第四晚赴谁的约）、`A4a`（见月申请/授权）、`A4b`（程放录音）、`A5a`（晚棠责任）、`A5b`（陆景行合作/竞争）、`A6a`（第七天翻案）、`UNWRITTEN`、`A6b`、`A7a`、`A7b`。
- 恋爱关键抉择：`t03` / `s03` / `l03` / `g03`，区分公开非排他、排他约定、慢一点、朋友和拒绝。关系承诺、知情同意、多人冲突仍由原引擎处理。
- 镜头：一屏只显示一个人一小段话；2 个简短情境镜头→选择；部分场景保留正典意向选择后再出现实际行动，**第一层意向不谎称为剧情后果**。每个动作直接写明可理解的代价，而不是提供技术选项名称。
- 后果：先展示真实引擎原回复中关键人物的一句，再展示一条与 `choice.effects` 的持久 `set` 标志相匹配的差异回应；刷新中途不丢失。没有匹配标志则拒绝冒充后果。
- 回收：首演没救成/成功会影响唐映雪第二天回话；签过责任单会在次日、第五夜和第七天受到程放施压；尊重私人照片限制影响见月的工作讨论；曾联系晚棠/合作陆景行也会有对话回调。这些都读取 `state.f`，不是另写无约束的虚拟恋爱数值。
- 低矮屏 320×568 使用两选一页、其余三选一页，所有选项仍可通过「上一组/下一组」触达，不使用内部滚动或缩字号，焦点可见且触点≥44 px。长正文与原始选后回复仍存于原生剧情数据、只读历史，不能从数据库中删去。

## 正典保护与工程证据

1. `data/STORY.json`、`tools/engine.mjs` 均没有修改，源故事 228 场、751 底层选择及旧存档重放语义不变；无新虚假好感度或奖励计数。
2. `node tools/test-romance-v11.mjs`：逐一检查 18 场、79 真实 choice ID 无遗漏，每个差异后果对应至少一个真实 `set` 状态写入。
3. `node tools/generate-romance-v11-fixtures.mjs`：只用引擎 `choose/replay` 从 ENTRY_WAKE 走到 21 天完结，并生成 18 个可重放的真实中间进度；不以伪造 flags 注入页面。
4. `python tools/test-romance-v11.py`：23 个选项剧情浏览器用例（含分页、坏结局、恋爱排他约定）× Chromium / WebKit；校验单人台词、按钮可触达、没有溢出、真实状态、选后即时反馈、刷新恢复。
5. 本机隔离环境的 Chromium 拦截 `http://127.0.0.1`；已使用 `R4_LOCAL_HTML=play.html` 弱模式的 `set_content` 通过 23 例。**正式 HTTP Chromium/WebKit 只有 GitHub Actions Run 实际通过后才能写“通过”。**
6. 本次未新增合格的独立后半段 CG。尝试制作出的带字分镜宣传板一律不收录；ADV8 11 张 CG 仍为暂用场景，V11 需要后续制作第 2/3/5/7 天的原生新镜头，这项正式美术验收明确 BLOCKED。

## 后续/发布限制

- 原 228 个场景不是全篇都完成新的 VN 演出：本轮改造明确覆盖 18 个核心抉择场景，其余仍沿用已通过工程回归的逐人分页阅读器。
- 未做物理 iPhone / Android 真机手感、玩家盲玩、CG 1536×2400+ 母版、商用来源审查。PR 保持 Draft，不得以工程 CI 通过代替商业/审美验收。
- 用户核心体验是否真正更爽，需实测首 30 秒理解、第一夜签字坏结果承受感、第三天路线差异和第七天翻案的剧情记忆；测试指标应是具体的玩家行动和误解，不是硬造一个留存百分比。
