## 原项目已确认的体验根因
来自实际 `tools/preview-ui.js`、`tools/preview.css`、`tools/preview-template.html`：
1. `storyHTML()` 输出 `meta + sceneBanner + rowsHTML + controls` 的自然文档流；对白是一串 `.line.dialogue` / `.line.narrator` 形式的网页段落，不是底部定点对白阅读器。
2. r4.2 已有原创 SVG 人像，但仅出现在横幅和日程卡片等区域，人物没有占据视觉小说的核心场景区域。
3. 现有一次分页可累计至 190 字/4 节拍，移动设备易成为滚动阅读；继续按钮在正文后部。
4. 首屏虽做了真正三选一，仍是说明文字 + 三个选项 + 隐藏完整开场，移动端阅读负担偏大。
5. `menuHTML()` 的十项入口全部平铺，和剧情沉浸界面没有阅读层级。
6. `@schedule` 的人物卡片依旧是网页导航式操作；相处反馈宜切换到人物场景。
7. 文字行为与存档逻辑已有比较严格的保护：`renderToken`、`revision`、`choicePage`、`localStorage` 冲突及导入校验；不可为了换 UI 破坏。

## 推荐结构：单手竖屏，场景优先
优先级依次：①剧情真实选择可达 ②一屏可看懂 ③人物/环境有情绪 ④单手操作 ⑤历史回看/存档可用 ⑥动画/声音锦上添花。
- 参考宽度 360–430 CSS px，处理 320 宽、640 高、20% 系统文字放大及安全区，宽屏仅居中模拟手机。
- 普通剧情：顶部 45px 左右轻量控制，中部 45–60% 是场景背景和人物，底部 30–45% 为可滚动文本台，场景不与文本整体上下滚动。
- 选择时：叠加 2–3 个大按钮；在小屏幕只滚动面板，不要求滚动整张网页；内部 5–6 个动作不能仅靠视觉分页冒充满足用户「一个决定通常 2–3、最多 4」的规则。
- 原著记忆用一条轻量可展开的强调文本，默认不抢占角色视觉空间；重要因果仍必须在选择前被读到。
- 大字与无动画设置；读档/回看/重选/收藏进菜单二级，而不是与主剧情同层。
- 按钮 >=44px，尊重 prefers-reduced-motion，断网不应影响必要交互。
- 立绘优先做 4 位女主统一规范（半身切分、表情至少中性/喜悦/警惕/难过、层级、手持道具），画风和内容需独立制作，禁止拷贝竞争作品。
- 继续点击整片对白区域只可在确认无分支时使用，触控拖动不能导致误选；保持 data-revision / data-render 防双击。

## 必须在正式代码接入前验证
1. 先保留 r4.2 本源，以 `tools/preview-ui.js` 和 `tools/preview.css` 的旁路新版布局分支实现；`build-preview.mjs` 生成三份受控产物，严禁手改 `runtime.mjs` 和 `play.html`。
2. 从真实 `renderScene()` 返回每个节拍；“读一句再继续”的 UI 变化应只动显示游标，不应记入 `state.history` 命令列表。
3. 首次三选一选项 `canon`、`rescue`、`investigate` 必须首屏可达；`ENTRY_WAKE` 说明仍显示原著背锅风险。
4. 读取 r4.2 存档时如需增加 UI 游标字段应向后兼容，旧存档、不匹配故事哈希及其他浏览器标签页不能覆盖。
5. 四人普通触控直达结局、重新选择、回看、单/双页存档冲突、中文大字、320/360/390/430 CSS px、短屏、iOS Safari 和 Android Chrome 实机；视觉盲审另独立出报告。
6. `npm run verify`、根仓库 `pnpm verify`、原生 HTTP `test:browser` 是工程最低门槛；每个证据带当次 git HEAD 与故事 hash。
7. 严格的 16 种 5–6 底层行动，需要另立内容结构重构任务，不可为了客户端改造把合法分支藏掉或删除。
